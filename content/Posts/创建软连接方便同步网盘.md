以下是CMD命令，Powershell命令是另外的

> [!CMD]
> 
> mklink /D "Folder1" "Folder2"

> [!NOTE]
> Folder1：在什么地方创建？绝对目录，包含目标目录名
> 
> Folder2：要被复制的目录名，推荐使用绝对目录
> 
> /D使用了软连接，代表源一旦被删除，对应的软连接位置也被删除。反之则不成立。
> /H 硬链接，任何一个位置存在文件则不删除文件。修改也会同步，但只能用来克隆文件，不能克隆文件夹
> /J 作用类似于/D但访问路径不同

# 以下是AI解释
## /D /H /J 的区别是什么？

在 Windows 的 mklink 命令中，/D、/H 和 /J 是不同的参数，用于创建不同类型的链接。它们的区别如下：

1. /D - 目录符号链接 (Directory Symbolic Link)
   - 创建一个指向目录的符号链接
   - 可以跨越驱动器
   - 在文件资源管理器中显示为快捷方式图标
   - 例如：mklink /D LinkName TargetDirPath

2. /H - 硬链接 (Hard Link)
   - 创建一个指向文件的硬链接（不能用于目录）
   - 必须在同一驱动器上
   - 在文件资源管理器中看起来像普通文件
   - 例如：mklink /H LinkName TargetFilePath

3. /J - 目录联接 (Directory Junction)
   - 创建一个指向目录的联接点
   - 可以跨越驱动器
   - 在文件资源管理器中显示为快捷方式图标
   - 例如：mklink /J LinkName TargetDirPath

主要区别：

1. 适用对象：
   - /D 和 /J 用于目录
   - /H 只用于文件

2. 跨驱动器：
   - /D 和 /J 可以跨驱动器
   - /H 不能跨驱动器

3. 兼容性：
   - /J（目录联接）在较旧的 Windows 版本中更兼容
   - /D（目录符号链接）在某些旧应用程序中可能不被正确识别

4. 删除行为：
   - 删除 /D 和 /J 创建的链接不会影响目标目录
   - 删除 /H 创建的硬链接会减少文件的链接计数，当计数为零时文件才会被删除

5. 权限要求：
   - 创建 /D（符号链接）通常需要管理员权限
   - 创建 /J（目录联接）和 /H（硬链接）不一定需要管理员权限

在大多数情况下，对于目录，/J 是最常用和最兼容的选项。而对于文件，只能使用 /H 创建硬链接。/D 提供了更现代和灵活的符号链接功能，但可能在某些情况下遇到兼容性问题。


## /D 和 /J 没有区别吗？ 子目录呢？

您提出了一个很好的问题。确实，/D 和 /J 有一些重要的区别，尤其是在处理子目录时。让我详细解释一下：

/D（目录符号链接）和 /J（目录联接）的主要区别：

1. 实现机制：
   - /D 创建的是符号链接，是 NTFS 的一个特性。
   - /J 创建的是目录联接，是基于 NTFS 重解析点实现的。

2. 兼容性：
   - /J 在较旧的 Windows 版本中更兼容。
   - /D 在 Windows Vista 及以后版本引入，某些旧应用可能无法正确识别。

3. 子目录行为：
   这是最关键的区别之一：
   - /D（符号链接）：当访问子目录时，路径会保留符号链接的部分。
   - /J（目录联接）：当访问子目录时，路径会被解析为实际目标路径。

4. 跨网络和跨设备：
   - /D 可以指向网络位置或不同设备。
   - /J 主要用于本地驱动器，虽然也可以指向网络位置，但不太推荐。

5. 安全性：
   - /D 创建时通常需要管理员权限。
   - /J 创建时不一定需要管理员权限。

子目录行为示例：
假设我们有以下设置：
- 目标目录：D:\RealFolder
- 链接位置：C:\LinkFolder

使用 /D 创建符号链接：
```
mklink /D C:\LinkFolder D:\RealFolder
```
访问 C:\LinkFolder\SubDir 时，系统认为路径是 C:\LinkFolder\SubDir

使用 /J 创建目录联接：
```
mklink /J C:\LinkFolder D:\RealFolder
```
访问 C:\LinkFolder\SubDir 时，系统会将其解析为 D:\RealFolder\SubDir

这个区别在某些情况下很重要，特别是当程序需要知道"真实"路径时。使用 /J 可能会导致程序误认为它在访问 D:\ 驱动器，而不是 C:\ 驱动器。

总结：
虽然 /D 和 /J 在表面上看起来相似，但它们在处理子目录、兼容性和某些特定场景下的行为上有明显区别。选择使用哪一个取决于您的具体需求和使用环境。
